## Goal and implementation

Prove recovery across real processes and make release activation/rollback atomic without an external service. The existing importer remains canonical. `scripts/manage-corpus-release.mjs` adds only release-state management around completed importer outputs: each candidate is a direct child of `release/runs`, accepted/quarantine hashes must match its completed manifest, and a deterministic `seal.json` binds the immutable artifact set before atomic replacement of `current.json`.

Repeated publication of the active run is a true no-op. A new publication appends the old run to pointer history; rollback verifies the prior sealed run before atomically selecting it. Incomplete/corrupt runs, checksum or seal drift, outside/nested paths, and unsafe physical aliases fail before pointer mutation. No database, object storage, provider, dependency, or production mock was added.

## Independent finding and fix

The first verifier pass found that lexical path confinement could be bypassed with a Windows junction, activating a target outside `runs/` and writing its seal there. A regression test reproduced the exploit. The shared boundary now rejects `lstat` symbolic links/junctions and uses `realpath` to require a physical direct child. The preserved and fresh exploits then exited 1, created no outside seal, and left the pointer unchanged.
