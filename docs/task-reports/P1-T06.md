## Defect and minimal fix

The declared `analysis.v1` type had no runtime trust boundary. Non-deep plies were placeholder facts with zero evaluations, empty moves/candidates and a false Stockfish claim; review used derived display objects, learning stored generic labels, and Coach accepted unchecked facts.

`assertAnalysisFactV1` now verifies legal FEN transitions, exact played/best SAN and UCI, evaluations, non-negative CPL, classifications, skill tags, non-empty anchored candidates, real `stockfish_wasm` source and timestamps. `assertGameAnalysisV1` enforces the game ID and one ordered fact per ply. The existing `(gameId, ply)` pair remains the stable evidence identity, so no schema version or Decision Gate was needed.

The two-pass analyzer now emits real shallow facts for every ply and replaces only selected plies with deeper facts. Review exposes the same fact identity/source/moves/tags on an accessible selectable row, learning accepts only validated facts, and Coach validates facts before building pre-move context.

## Production defect found

The first real browser replay exposed a worker-only boundary case: the last streamed PV head could differ from Stockfish's final `bestmove`, causing strict validation to reject the review. A RED regression reproduced it. The analyzer now keeps the full PV only when it starts with final `bestmove`; otherwise it records the truthful one-move candidate line `[bestmove]`.
