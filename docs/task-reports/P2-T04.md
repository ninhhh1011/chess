## Implementation

`scripts/import-lichess-puzzles.mjs` is the canonical CLI. It supports official network or local input, accepted/quarantine/manifest/checkpoint outputs, resume, rating/theme/popularity filters, accepted limit, batch size, dry-run, validation-only, controlled abort, and explicit dataset version.

The data path is fully streaming: network/file stream → leading-skippable-frame adapter → Node native `createZstdDecompress` → fatal incremental UTF-8 decoder → line parser → pre-retention filters → fixed batches. It uses Node standard APIs plus the already-installed `chess.js`; no CLI or compression dependency was added.

Every accepted row preserves the real Lichess ID and source URL, source FEN and preceding move, derived solver FEN/side, complete replayed solution, rating/deviation/popularity/plays/themes/opening/game/daily metadata, CC0 provenance, source/run/parser/validator versions, and raw/normalized/canonical SHA-256 values. Invalid records and both duplicate classes are separately quarantined.

Downloads use exclusive creation and remove only an incomplete task-owned destination on failure. Accepted/quarantine writes are append-only partial files with flush/fsync before atomic checkpoint replacement; final outputs are renamed only after completion. Existing final, partial, manifest, or checkpoint paths are never overwritten by a fresh run.

## Checkpoint, resume, and determinism

The checkpoint binds the source/dataset/config/checksum/importer/parser/validator versions, absolute output paths, original retrieval timestamp, committed source-row count, all counters, durable byte lengths, import-run ID, update time, and status. Resume rejects corrupt, stale, dataset/config/path-mismatched checkpoints, truncates partial outputs only to recorded durable lengths, rebuilds accepted ID/key sets, and preserves the original `retrievedAt` across the run.

Because arbitrary seeking in the compressed stream is unsafe, resume restarts decompression and skips the committed source-row count. It is correct and bounded but not O(1); byte-for-byte idempotency and rollback remain the explicit P2-T06 scope.

Generated timestamps are excluded from reproducible content identity. Two clean runs and the interrupted/resumed run all produced `c836c4470ffc4289945d2e48f987ad1849926f7cb526002bb81e4f9511b00338`; byte-level output checksums legitimately differ with run metadata.
