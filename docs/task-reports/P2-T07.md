## Trust and rollback boundaries

`scripts/build-corpus-delivery.mjs` accepts only a completed `puzzle-record.v1` import whose accepted-file checksum, source checksum, record count, and PASS validation report agree. It chunks records in a temporary run and renames the completed run before atomically moving the pointer. Existing and rollback runs have their manifests and every chunk checksum revalidated before activation; corruption leaves the pointer bytes unchanged.

`loadProductionCorpus()` pins the pointer/manifest schemas, official Lichess URL, CC0 license, exact approved dataset/source SHA, chunk paths/counts/checksums, every `PuzzleRecord` checksum/contract, record source/license provenance, and aggregate count. It returns no records on any failure. `Exercises` then uses the verified corpus or keeps the five bundled exercises with an explicit unavailable notice. Real records visibly link to the Lichess puzzle and CC0 license.
