## Goal and implementation

Define one strict, versioned record contract for future real corpus imports. `PuzzleRecord`/`PuzzleRecordInput` now define `puzzle-record.v1` with 16 required fields covering internal/source IDs, source URL/version/publication and retrieval timestamps, license ID/URL, source and record SHA-256, FEN, complete UCI move sequence, rating, and themes.

`src/services/puzzleRecord.ts` is the single runtime boundary. It canonicalizes fields in a fixed order, hashes with platform Web Crypto SHA-256, pins a deterministic fixture digest, and rejects missing, unknown, malformed, or post-hash-mutated records. No package, provider, source, or license was changed.

## Adversarial finding and fix

The independent verifier reproduced a real trust-boundary defect: the required-field check read values through the prototype chain, while object rest canonicalized only own fields. A crafted object with zero own required fields and the SHA-256 of `{}` could pass.

The root fix is one own-property guard at the shared validation boundary: `Object.hasOwn(record, field)`. A core regression covers inherited required fields. The verifier preserved the initial 57/58 failure, then reran the exact exploit and all gates successfully.
