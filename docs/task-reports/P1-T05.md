## Defect and minimal fix

The old shallow pass analyzed each post-move FEN twice at different Elo values, so it did not compare the position before and after a move and often selected no deep candidates. Deep analysis then used the post-move FEN, which proposed the opponent's reply instead of an alternative to the played move. Engine errors were silently skipped, and the production review button duplicated a separate analysis loop.

`analyzeGame` now evaluates the initial position once and each post-move position once, reuses the prior result as the next pre-move evaluation, computes mover-aware CPL, selects candidates deterministically, and deep-analyzes each candidate's `fenBefore`. Both passes fail with exact location context. The production review button now calls this single service. No dependency, provider, model, storage, or schema changed.

## Contracts and tests

- Focused tests cover both pass failures and both cancellation points. The deterministic 40/80 unit test is explicitly mocked and makes no latency claim; P1-T08 owns fresh real-WASM latency.
