## Goal and implementation

Replace the legacy sampled, warning-only corpus check with one canonical fail-closed validator. `scripts/validate-puzzle-corpus.mjs` streams JSONL with fatal UTF-8 decoding and validates every accepted record; there is no sample option or whole-corpus buffering. `scripts/verify-corpus.cjs` is now only a compatibility wrapper that forwards all arguments and propagates the canonical exit status.

The validator combines PuzzleRecord v1 contract checks with Lichess-specific gates: FEN, source-FEN plus preceding-move derivation, side to move, full legal `chess.js` solution replay, rating, official provenance/URL, exact CC0-1.0 license, source/row/canonical/normalized checksums, import-manifest agreement, duplicate source IDs and normalized keys, and the pinned official theme taxonomy. The taxonomy is pinned to Lichess commit `50139702e66d67747e5ac0a6482b275f348f0dcd`; independent comparison found 75/75 exact themes.

Record failures are written incrementally to quarantine with exact reason codes and counts. Manifest or accepted-record gate failures return exit `2`; fatal input/UTF-8/usage failures return `1`; a clean corpus returns `0`. Manifest source hashes must be valid SHA-256 values, and the accepted output is independently hashed before validation succeeds.
