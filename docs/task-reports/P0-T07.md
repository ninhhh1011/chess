## Root cause and scope

The shipped exercise data passed a validator that existed only inside its test file, so the production page did not reject invalid records. The persisted training profile and daily plan had no schema version; a legacy plan was retained unchanged, producing an empty canonical task list, while the legacy-migration test never loaded the legacy value it declared. The change is limited to shared validation, storage normalization, and stronger tests. No dependency, external service, generated dataset, theme, or layout changed.

## Implementation

- Added the shared `exerciseValidator.js` trust boundary and made the Exercises page render only records that pass required-field, FEN, game-state, legal-move, capture, promotion, and checkmate checks.
- Added `profile.v1` and `training.v1` to persisted contracts.
- Added one normalizer that accepts canonical tasks, migrates the legacy lesson/exercises/opening/challenge shape, drops malformed tasks, and returns `null` when regeneration is required.
- Kept the existing four task types and routes; no new abstraction, dependency, or UI feature was added.
- Replaced the vacuous new-user browser assertion with exact rendered task-type and non-zero progress-total assertions.
