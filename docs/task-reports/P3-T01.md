## Outcome

The local profile is now a versioned `profile.v2` document with a nested `learningPersistence.v1` contract. It serializes game reviews, trusted `AnalysisFact` records, puzzle attempts, skill state, training plans, and sync metadata. Each entity has a versioned schema, stable identity, canonical ISO timestamps, duplicate-ID checks, and required cross-record references.

The implementation keeps the existing localStorage and Supabase JSON profile boundary. It does not add or change a database schema, provider, dependency, or deployment service, so no Decision Gate is needed.

## Migration and invalid-state behavior

Existing `profile.v1` data migrates to `profile.v2` while preserving progress, timestamps, revision, and a stable identity across subsequent reads. Daily plans receive stable native UUID identities and normalized timestamps. A normal mutation increments the profile and sync revisions exactly once. Cloud download, conflict selection, and sync prompts normalize both legacy local and cloud documents before comparing them.

Unsupported schema versions and malformed `profile.v2` entities fail closed. The original persisted bytes remain untouched so user data is recoverable rather than silently replaced. The entity validator also rejects invalid timestamps, duplicate IDs, malformed facts, and orphaned review-to-fact references.

The independent verifier found that `AnalysisFact.analyzedAt` still accepted a locale-form date string. A RED regression reproduced it at the shared `assertAnalysisFactV1` trust boundary. The first exact-string correction was deliberately rejected after the full suite proved it also excluded valid ISO 8601 values without explicit milliseconds. The final boundary accepts equivalent UTC ISO forms with or without milliseconds and rejects locale strings; the AnalysisFact, persistence, daily-plan, learning-loop, and full Coach grounding focused gate then passed 90/90 tests.
