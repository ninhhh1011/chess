## Defect and minimal fix

The shared CPL function treated mate distance as an absolute difference, returned an ambiguous fixed value for mate/cp transitions, and allowed negative CPL from engine noise. The analyzer also inferred the mover from odd/even ply rather than the pre-move FEN. Skill tagging still expected a negative evaluation delta even though production supplied CPL, and the fact validator checked only the first move of a candidate PV. The Stockfish service concatenated every streamed PV instead of retaining the latest line.

`calculateCPL` now maps cp and signed mate evaluations to one ordered scalar and clamps loss to zero. `calculateMoverCPL` applies the same calculation symmetrically from the mover recorded in `fenBefore`. The analyzer uses that boundary, skill tags consume positive CPL, every PV move is replayed by chess.js, and the worker result keeps the most recent PV line. Classification thresholds remain unchanged: 0, 10, 30, 80 and 200 cp.

Review evidence buttons expose the validated turn, before/after evaluation, CPL and classification alongside the existing evidence ID, moves and engine source. This is technical evidence metadata; the visible product layout and labels are unchanged.
